# Командование: фельдмаршалы, генералы, цвета, планы (B1 — версия симуляции 35, B3 — 36)

Решения владельца (2026-11-01): у фельдмаршала есть до `MAX_ATTACHED` прикреплённых генералов; цвет задаётся детерминированной палитрой; игрок может перекрасить своего
фельдмаршала; генералы наследуют цвет; неприкреплённые серые. **«Прикреплённый генерал» = армия группы** (в группе армий у каждой армии свой генерал; отдельного
прикрепления генерала без армии нет), решение принято владельцем словом «ОК» на мой план.

## Что есть в коде
- Группа армий и её фельдмаршал: `military/ArmyGroup.{hpp,cpp}` (`ArmyGroup`: `id`, `marshal_id`, `execute_orders`, `colour_index`). Группы есть только у стран с технологией
  организации армии (`has_army_organisation`), не больше `MAX_ARMY_GROUPS` = 12.
- **Лимит прикреплённых армий (генералов)**: `get_marshal_max_attached` = `ov_war.MARSHAL_MAX_ATTACHED` (12) + модификатор страны `attached_generals_add`, не больше
  `ov_war.MARSHAL_MAX_ATTACHED_LIMIT` (48). Модификатор регистрируется как эффект технологии (`ATTACHED_GENERALS_TECH`), технологии `general_staff`, `mobilisation_planning`,
  `operational_planning` дадут +12 каждая (этап B5, пока данные не выданы).
- **Палитра**: `ov_data/common/ov_command/palette.txt` (`colour = { r g b }`, 16 цветов); нет файла или он пуст — встроенные 12 цветов (`CommandPalette::use_builtin_colours`).
  Новая группа берёт первый цвет палитры, которого нет у других групп страны (если заняты все — наименее используемый, первый из них), поэтому цвета одинаковы в каждом
  прогоне. Индекс цвета в хеше состояния (`colour_index`).
- Команда игрока `set_army_group_colour(страна, группа, индекс)` (`GameAction`): перекрашивает фельдмаршала любым цветом палитры (повтор цвета другой группы разрешён).
- Ежедневное обновление (`update_army_groups`): цвет вне палитры (другая палитра, старое сохранение) заменяется первым цветом палитры; армии сверх лимита (лимит упал) выходят
  из группы, начиная с последних армий страны.
- Генералы, уже сидящие в армиях при старте игры, не трогаются: групп при старте нет (игрок создаёт их сам), поэтому переносить нечего.
- Мост в интерфейс (`PlayerSingleton`): `get_army_groups()` даёт `colour_index`, `colour` (Color) и `max_attached` страны; `get_army_details()` даёт `army_group_colour`;
  `get_generals()` даёт `command_colour` и `command_group_id` (серый и 0, если генерал не в командовании); `get_command_palette()` и `set_army_group_colour(group_id, colour_index)`.
- Портреты: этап B2 (интерфейс), из спрайтов Vic2 по группе культур, пока силуэт.

## Проверка
- Дамп `headless -b <Vic2> --dump-command`: строки `COMMAND_PALETTE`, `COMMAND_LIMIT`, `COMMAND_COUNTRY` (армии, генералы, лимит, группы), `COMMAND_GROUP` (цвет, фельдмаршал, прикреплено/лимит).
- Самотесты `command: ...` и `commanders: ...` (палитра, цвета групп, перекраска, лимит с границами).

## B3. Фронты и планы (версия симуляции 36)

**Что было до правки** (дамп `headless -b <Vic2> --dump-front -e 1`, переменные `OV_FRONT_PAIR=FRA,PRU`, `OV_FRONT_DAYS=150`; сценарий: война двух соседей, ИИ ведёт обе стороны):
работает: автофронты строятся каждые 10 дней по границе с врагом, все армии назначаются на фронт, фронт в режиме «наступление», дивизии расходятся по линии (армий на фронте становится
больше), армии идут в провинции врага, провинции переходят из рук в руки (Франция против Пруссии: за 60 дней 1–2 провинции, дальше позиционная война). Не работает/нет: понятия «план»
(цель + приказы + запуск и остановка), связи фронта с фельдмаршалом, остановки приказов. Фронты игрока (`create_front`, `set_front_mode`) исполнялись всегда, без выключателя.
Фронты не входили в хеш состояния.

**Что сделано:**
- Фронт получает `group_id` (кто его держит). Фронт **без группы** работает как раньше (автоплан ИИ и ручные фронты игрока, всегда с приказами). Фронт **с группой** получает приказы
  только пока активен план этой группы на этот фронт (`WarManager::is_front_commanded`); автоплан такой фронт не трогает (линию, режим и армии не меняет, не удаляет).
- У группы (фельдмаршала): фронты, которые она держит (`Front::group_id`), и **один план** (`plan_front_id`, `plan_mode`: 0 наступление, 1 удержание; `plan_active` — галочка).
  Команды: `set_army_group_front` (держать/отпустить фронт; фронт чужой группы нельзя), `set_army_group_plan` (задать фронт и режим; запущенный план останавливается),
  `set_army_group_plan_active` (галочка: нужен план и фельдмаршал; армии группы встают на фронт, режим фронта = режим плана).
- Остановка плана (галочка выключена, смена плана, группа удалена, фельдмаршала сняли, фронт пропал — ежедневное обновление) отменяет движение армий фронта; они стоят на местах,
  армии в бою остаются в бою.
- В хеш состояния теперь входят фронты (id, группа, режим, число провинций и армий) и поля плана группы: **CHECKSUM сценария с войнами изменился осознанно**, база снята заново.
- Мост: `get_army_groups()` даёт `front_ids`, `plan_front_id`, `plan_mode`, `plan_active`; `get_front_summaries()` даёт `group_id`, `commanded`; команды `set_army_group_front`,
  `set_army_group_plan`, `set_army_group_plan_active`.
- Проверка: `--dump-front` с `OV_FRONT_GROUP=1 OV_FRONT_STOP=80` (страна игрока, фельдмаршал держит фронт против врага; строки `FRONT_GROUP`): план идёт, армии группы наступают и занимают
  провинцию, на 80-й день остановка, после неё движения нет. Самотесты `plan: ...` (18 проверок).

**Допущения:** «подготовка» (третий режим из задания) пока не сделана: есть наступление и удержание (`plan_mode` 0 и 1); задать цель плана точнее фронта (провинцию) нельзя — цель задаёт
линия фронта и режим. Линии фронта и стрелки плана на карте цветом фельдмаршала рисует интерфейс (B2).
