# Рынок, пошлины, бюджет, выбор армий, дальность прорисовки

Дата: 2026-10-13. Всё **собирается** (Linux, GCC 13), но игру запустить было нельзя: поведение и интерфейс не проверены.
Симуляция: ветка `diplomacy-actions` репозитория `OpenVic-Simulation-private`; расширение/GDScript: этот репозиторий.

## 1. Рынок: AI и ручная закупка (экран торговли)

Файл: `country/CountryInstance.cpp`, `manage_national_stockpile`. Раньше автоматические («AI») товары только докупались до
«потребности правительства» (она нигде не вычисляется, поэтому всегда была 0 и ничего не происходило), а избыток никогда
не продавался. Теперь для каждого товара страны:

| Режим | Целевой запас | Если запас ниже | Если запас выше |
|---|---|---|---|
| **AI** (галочка «автоматически») | потребность правительства (сейчас всегда 0) | докупает до цели | **продаёт весь избыток**, то есть держит на складе 0 |
| **Ручной, «покупать»** | значение ползунка | докупает до значения ползунка | не продаёт |
| **Ручной, «продавать»** | значение ползунка | не покупает | продаёт всё сверх значения ползунка |

- Деньги на закупку берутся из остатка бюджета (`available_funds`), как и раньше: если бюджет расходов съедает всю казну,
  докупать будет не на что.
- Иконки покупки/продажи в списке товаров для AI-товаров теперь показывают продажу/покупку относительно потребности
  правительства (а не относительно ползунка) — `singletons/TradeMenu.cpp`.
- **Как проверить:** `Торговля` → выбрать товар со складом → включить «автоматически»: за пару дней склад должен упасть до 0
  (продан на рынок, растёт казна). Выключить «автоматически», режим «покупать», поставить ползунок на значение выше склада:
  склад должен вырасти до значения (если есть деньги), цена в списке при этом растёт.
- Что не сделано: `government_needs` / `max_government_consumption` (потребность армии, флота, строек) нигде не рассчитываются
  (TODO в `calculate_government_good_needs`). Поэтому AI не закупает товары для армии. Это следующий шаг экономики.

## 2. Пошлины

Что было: пошлина считалась только для покупок населения (`Pop::after_buy`); ползунок и бюджет уже работали.
Что сделано (`economy/production/FactoryInstance.{hpp,cpp}`):
- **заводы тоже платят пошлину** на импортируемые входные товары (`apply_tariff`, доход идёт в казну страны-владельца);
- при размещении заказа часть бюджета завода резервируется под пошлину, чтобы бюджет не уходил в ноль только из-за пошлины.

Как проверить: экран «Бюджет», ползунок пошлины (если он не двигается — предел задаёт `max_tariff` из политики правящей партии и
технологий; при нулевом пределе ползунок стоит на месте — это правило игры, а не ошибка кода). После включения пошлины в
строке «доход от пошлин» должна расти сумма, цены на импортные товары для населения выше.

## 3. Круговые диаграммы бюджета

`components/budget/BudgetMenu.{hpp,cpp}`: три диаграммы (`chart_0..2` — низший, средний, высший класс) заполняются по типам
населения своего слоя: цвет среза = цвет типа (аристократы, капиталисты, рабочие...), размер = налогооблагаемый доход этого
типа (пока доход не посчитан — численность). **При наведении на срез показывается класс и доля**, например «Аристократы: 45%».
Диаграмма долга пока не заполняется (нет долгов).

## 4. Выбор армий не пропадает

`UnitBanners.gd`: выбор теперь хранится по **id армий**, а не по иконке (иконка меняется при смене провинции, из-за чего выбор
терялся). Армия остаётся выбранной, пока вы не снимете выбор, её не уничтожат или не кликнете по карте.
**Shift + правый клик** добавляет провинцию в конец маршрута (`queue_army_move`, `order_move(..., append)` в симуляции): армия
пойдёт по очереди через все точки, выбор сохраняется. Обычный правый клик заменяет маршрут.

## 5. Иконки армий и дальность прорисовки

- Иконки армий (`UnitBanners.gd`) стали на **20% ближе** (скрываются на 20% ниже по высоте камеры) и на **20% меньше**.
- Новая настройка **Draw Distance (%)**: Настройки → Video, ползунок **−50..+50**, по умолчанию **0**. Она масштабирует
  дальность прорисовки иконок армий, **моделей юнитов и зданий** (`ModelManager.gd`: модели видны, пока камера ниже
  `порога × (1 + значение/100)`). Модели больше не переключаются сигналом `detailed_view_changed` (соединение убрано из
  `GameSession.tscn`), видимость считается каждый кадр от высоты камеры.
- Файлы: `GameSettings.gd` (настройка `video/draw_distance`), `MapView.gd` (`get_camera_height`, `get_detailed_threshold`),
  `ModelManager.gd`, `UnitBanners.gd`.
- Названия настройки в локализации нет, показывается английское «Draw Distance (%)».

## 6. Сборка и проверка в целом
Пересобрать (`cmake --build --preset windows-x64-editor`, MSVC 14.44), перезапустить редактор, подтянуть сабмодуль.
Если GDScript не парсится, Godot покажет ошибку при открытии проекта (`UnitBanners.gd`, `ModelManager.gd`, `GameSettings.gd`).
