## 1. Лимит снабжения провинции (задача A)

### Формула (единая, все множители собраны в одном месте)
```
база          = SUPPLY_LIMIT_BASE (по умолчанию 1.0) * лимит_типа_провинции
скобка        = база * (1 + SUPPLY_RAIL_BONUS_PER_LEVEL * уровень_железной_дороги) * технологии_лимита * (1 + бонус_родной_земли)
ёмкость       = скобка * коэффициент_территории * (1 + бонусы_генерала − временные_дебафы)
```
- Ёмкость считается **для страны армии**: «ёмкость провинции P для страны X». Одна и та же провинция даёт разной ёмкость армиям разных стран (технологии, бонус родной земли), поэтому
  отстающий технологически противник имеет меньше снабжения даже на своей земле. Враги не делят нагрузку друг с другом; армии союзников/своих в одной провинции делят нагрузку
  (сумма потребностей), но каждая использует ёмкость **своей** страны.
- **Бонус родной земли** (`SUPPLY_HOME_BONUS = 5%`, технология добавляет ещё 5% — `SUPPLY_HOME_BONUS_TECH`, заглушка 0): действует **только на провинциях, которыми владеет страна армии**
  (не союзных, не захваченных) и стоит в скобке рядом с дорогами и технологиями.
- **Лимит типа провинции** = местность (`terrain.txt`: равнины/фермы 10, степь 8, лес/холмы/чаща 6, горы/джунгли/болота/пустыня 2) + статмодификаторы (`land_province` 5,
  `sea_zone` 10, `coastal_sea` 10, `base_values` 5, модификаторы провинции).
- **Железные дороги**: **складываются**, +10% за уровень (`SUPPLY_RAIL_BONUS_PER_LEVEL = 0.10`): уровень 3 = ×1.3.
- **Технологии лимита**: множитель **страны армии** (решено: ваши технологии, пока вы в чужой провинции), заглушка 1.0
  (`get_supply_limit_research_multiplier()` по образцу существующего `get_supply_research_multiplier()`).
- **Коэффициент территории** (раздел 2) зависит **только от технологий** и расположения захваченных провинций. Черты генералов и временные дебафы на него **не влияют**.
- **Множитель генерала/временных дебафов** стоит **только в общей формуле**, последним: `1 + бонус_генерала − временные_дебафы`, обе части пока заглушка 0 (значение ограничено ≥ 0).
- Нагрузка = суммарная потребность полков всех наших армий в провинции (для кораблей — как сейчас, без лимитов, см. вопрос 9).

### Пересчёт и хранение
- Производные значения провинции (`supply_limit`, `supply_load`, `supply_delivery`) хранятся в `ProvinceInstance`, обновляются: по событию (смена владельца/контроля, дорога,
  технология, вход/выход армии) и раз в день для провинций с армиями. Остальные 3000 провинций раз в месяц (для карты и подсказок) — отдельно решим в этапе 1.
- В хеш состояния входят только значения, влияющие на игру (поставка по армиям); подсказки и карта считаются из тех же функций.

### Что отображаем
- Подпись в панели провинции: «лимит X, нагрузка Y, поставка Z%», подсказка с разбором (раздел 7а).
- **Режим карты «Снабжение»** (цвет по `r = ёмкость_с_добором / нагрузка`; запас выше 100% — хватает, ниже — нехватка):

  | цвет | значение | `r` |
  |---|---|---|
  | тёмно-зелёный | хватает с запасом более 50% | ≥ 150% |
  | зелёный | запас более 25% | 126–149% |
  | голубой | запас 11–25% | 111–125% |
  | синий | хватает с малым запасом (до 10%) | 100–110% |
  | жёлтый | нехватка до 10% | 90–100% |
  | оранжевый | нехватка до 25% | 75–90% |
  | красный | нехватка более 25% | 50–75% |
  | тёмно-красный | нехватка более 50% | < 50% |

  Поверх — **контур границы «захваченной» территории** (наша + союзная + захваченная нами). Для провинций без армий — вопрос 6 (эталонная нагрузка). Пороги — в defines, так что
  палитру и границы можно менять.
- **Уведомления**: «армия X без снабжения» (когда `d` падает ниже порога `SUPPLY_ALERT_LEVEL`, по умолчанию 50%, и «снабжение восстановлено»), с возможностью выключить в настройках
  уведомлений; раз в 3 дня на армию максимум одно сообщение (без спама).

## 2. Коэффициент территории (снабжение вдали от своих земель)

### 2.1 Кто «свой»
Провинция **захвачена** (для расчёта), если её владелец или контролёр — **мы или наш «свой»**. «Свой» (функция `is_supply_friend(a, b)`) — страна, которая:
1. состоит с нами в **союзе** (`has_alliance_with`);
2. находится в той же **войне на нашей стороне** (союзник по войне, временный: пока длится война; после мира перестаёт быть своей);
3. дала нам **проход войск** (`has_military_access_to(мы → она)`, уже есть в дипломатии). **Договор о проходе войск автоматически включает снабжение**: отдельного договора
   о снабжении нет, второй раз его подписать нельзя. Страна с проходом войск считается для снабжения **союзной**: коэффициент территории 100%, добор у соседей работает, провинции
   в счёт «захваченных» (бонус родной земли — нет, он только для собственных). Направление одностороннее: проход у нас → снабжение у нас на её земле.

Не «свои» автоматически: **сфера влияния** (`sphere_owner`), **вассалы / марионетки / протектораты** — они только могут подписать договор о проходе войск (и тем самым о снабжении).

«Враг» определяется по войнам и владельцу провинции: коэффициент территории применяется, когда провинция принадлежит стране, с которой мы **воюем**
(или бесхозна / колония вне «своих»). На землях стран с военным доступом без договора о снабжении — вопрос 3.

### 2.2 Таблица (армия стоит на вражеской провинции `A`)
Считаем по **сухопутным** соседям. «Незахваченные между» — это провинции на пути от `A` до ближайшей захваченной, **сама `A` не считается**.

| ситуация | коэффициент | примечание |
|---|---|---|
| свои земли, союзные, уже захваченные (то есть `A` захвачена) | **100%** | |
| 1 соседняя захваченная | **90%** (`SUPPLY_NEIGHBOUR_ONE`) | технология поднимает до 100% |
| 2 и более соседних захваченных | **100%** | |
| соседних захваченных нет, но через **одну** незахваченную есть захваченные | **50%** (`SUPPLY_GAP1_BASE`) за первую захваченную **+10%** за каждую следующую (`SUPPLY_GAP1_STEP`), не больше 4 захваченных в счёте (`SUPPLY_GAP1_MAX_COUNT`) — до **80%** | дебаф 50%, а не 10% |
| через **две** незахваченные подряд | **25%** (`SUPPLY_GAP2_BASE`) за первую **+5%** за каждую следующую (`SUPPLY_GAP2_STEP`), не больше 5 в счёте — до **45%** | открывается технологией «современные армии»; она же ускоряет захват; со старта выключено (`SUPPLY_GAP2_ENABLED = 0`) |
| дальше или GAP2 не открыт | **10%** (`SUPPLY_FAR`) | технология поднимает до 20% |

### 2.3 Что я имел в виду (пример)
```
 [своя] — [В] — [В] — [А]        А — где стоит армия, В — вражеские, пока не захваченные
```
- Если рядом с `А` ничего своего нет, а через **одну** вражескую провинцию (`[В]` между) стоит захваченная — расстояние 2: считаем сколько разных захваченных провинций касаются
  соседей `А`. Одна — 50%, две — 60%, три — 70%, четыре и больше — 80% (потолок).
- Если между `А` и захваченной **две** вражеские провинции подряд — расстояние 3 («два незахваченных между армией и нашей провинцией», ваше уточнение): 25% + 5% за каждую следующую
  захваченную, до 45% — только после технологии; без неё эта ситуация даёт «дальше» = 10%.
- Расстояние 4 и больше — «дальше» = 10% (20% с технологией).
- Это и есть «дебаф вдвое жёстче и прирост вдвое ниже» из вашего описания: у расстояния 3 база 25% против 50% и шаг 5% против 10%.

### 2.4 Технологии
Параметры `SUPPLY_TECH_*` (пока заглушки 0): +10% к одному соседу (до 100%), +10% к «дальше», открытие расстояния 3, сдвиг баз. Итог **всегда ограничивается 0…100%** (даже если технологии
дадут больше). Черты генералов сюда **не входят**, они только в третьем множителе общей формулы.

## 3. Доставка снабжения, приоритет, соседние провинции (задача B)

### 3.1 Базовая модель
- Потребность армии `N` — как считаем сейчас (доля стоимости создания, множители похода и врага, ползунок бюджета).
- Для провинции: ёмкость `C` (раздел 1), нагрузка `L = Σ N_i` по армиям в ней. Доставленная доля **`d = clamp(C_eff / L, 0, 1)`**; если `L = 0` — `d = 1`; если `C_eff = 0` — `d = 0`.
- **Снабжение никогда не больше 100%**: доставленное армии не больше её потребности (`доставлено ≤ N`), `d ≤ 1`, уровень снабжения армии 0…1. Лишние единицы не накапливаются.
- Потерянная часть `(1 − d)` для полка пропадает, не копится в долг.

### 3.2 Соседние провинции (переменная `SUPPLY_NEIGHBOUR_EFFICIENCY`, 75%)
- Если ёмкости провинции не хватает на потребности стоящих в ней войск, она **добирает у соседних свободных провинций**: свободная часть соседа `F = max(0, C_соседа − L_соседа)`
  идёт в добор с эффективностью **75%** (`SUPPLY_NEIGHBOUR_EFFICIENCY = 0.75`): `C_eff = C + 0.75 * Σ F_соседей` (с запасом, чтобы не превысить недостачу).
- Берём только **прямых сухопутных соседей** (не цепочкой), только «своих» (раздел 2.1) или тех, где армия стоит на захваченной земле; сосед сначала обслуживает **свои войска**, и только
  потом его свободный остаток отдаётся соседям — это «приоритет войскам, которые находятся на провинции».
- Детерминизм: порядок обработки — по номеру провинции, два соседа не делят один остаток дважды (остаток уменьшается по мере выдачи); считаем **последовательно после** параллельного
  обновления провинций (чтобы не читать чужое состояние в потоках).

### 3.3 Приоритет армии (в пределах провинции)
- **стандартный** — отправляется ровно `N`, доходит `N * d`;
- **повышенный** — отправляется `N * min(2.5, 1/d)` (компенсирует потери), доходит `N * min(2.5 d, 1)`;
- **максимальный** — то же с потолком 5×.
(`SUPPLY_PRIORITY_INCREASED_MAX = 2.5`, `SUPPLY_PRIORITY_MAX_MAX = 5`.)
- Сверх нормы платит госзапас; если товара нет, армия получает что есть (вопрос 7). Порядок обслуживания в провинции: максимальный → повышенный → стандартный, при равенстве — по номеру армии.
- Приоритет **у каждой армии свой**. Во вкладке армий — **глобальный** тип; ручная смена у армии ставит флаг «свой приоритет» и отвязывает её от глобального (кнопка «вернуть к глобальному»).
- Уровень снабжения (множитель боевых характеристик) считается **по армии**: цель = ползунок бюджета × доставленная доля `d`, меняется на 2% в день; страновое значение остаётся для
  интерфейса как среднее.

### 3.4 Защита от ошибок (проверяем тестами)
- деление на ноль (`L = 0`, `C = 0`), отрицательные значения (бонусы генералов > 100%, дебафы), переполнение `fixed_point_t` (множители ограничены, суммы в `int64` недоступны — считаем по долям);
- все коэффициенты и доли — в диапазоне 0…1, ёмкость ≥ 0, приоритетный множитель ≤ потолка; сумма доставленного по армиям ≤ ёмкости + 0.75·остаток соседей;
- одна и та же провинция при разном числе потоков и перезагрузке из сохранения даёт те же значения (хеш состояния, версия симуляции растёт);
- армия вошла/вышла из провинции или провинция сменила владельца в тот же день — пересчёт идёт в фиксированном порядке (сначала владельцы, потом ёмкости, потом поставка).

## 4. Состав армий и шаблоны (задача C)

Структура (при открытой технологии): **армия → дивизии → полки**. Полк — минимальная единица (пехота, кавалерия, артиллерия…), как сейчас.

### 4.0 Технология организации армии — два режима
Технология **«Организация армии»** (название рабочее) открывается **только цивилизованным странам** (на старте её имеют цивилизованные страны; нецивилизованная получает её с вестернизацией).
Что она открывает: **дивизии, шаблоны, армии как объединение дивизий, генералов и фельдмаршалов, фронты и планы операций**. Реализуем как способность страны
`CountryInstance::has_army_organisation()` (хранится в состоянии и хеше, выдаётся автоматически, когда страна цивилизованна; имя и описание в локализации, видна в списке технологий/
подсказках); настоящая запись в дереве технологий — когда определим ветвь.

| | без технологии (нецивилизованные) | с технологией |
|---|---|---|
| единица управления | **группа полков**, как в Victoria 2: полки в стеке, **слияние и разделение** групп, перенос полков между группами | армия → дивизии → полки |
| шаблоны дивизий | **нет** (шаблоны открываются технологией; у нецивилизованных её на старте нет) | да |
| генералы/фельдмаршалы | **нельзя назначить** (интерфейс скрыт/недоступен) | да |
| фронты и планы операций | **недоступны**: только ручное управление группами (движение и приказы вручную) | да (и ручное управление остаётся) |

- При получении технологии (вестернизация) все группы полков превращаются в дивизии «вне шаблона» (раздел 4.2); при потере цивилизованности — обратно в группы, генералы снимаются.
- Снабжение (разделы 1–3) работает в обоих режимах: нагрузка считается по полкам, приоритет задаётся на группу/армию.

### 4.1 Дивизия и шаблон
- `DivisionInstance`: имя, шаблон (или «вне шаблона»), список полков, параметры (ширина фронта, организация, атака/защита, потребность в снабжении) — сумма/среднее по полкам.
- **Шаблон дивизии** (`DivisionTemplate`): имя и список слотов с типом полка; хранится в состоянии страны (игрока и ИИ), создаётся/меняется командами `GameAction`.
  **Создание шаблонов доступно только после открытия технологии** (4.0).
- **Стандартный шаблон цивилизованных стран: 3 пехотных полка + 1 кавалерийский.** У нецивилизованных шаблонов нет, поэтому отдельный шаблон им не нужен.

### 4.2 Войска, которые есть со старта («вне шаблона»)
- (Для стран с технологией.) **Не трогаем**: каждая стартовая армия превращается в дивизии «вне шаблона», в которых лежат те же полки в том же составе (число и состав как есть, никаких перекладываний).
  Для боя и ширины они считаются как обычные дивизии, но без значка шаблона.
- Кнопка **«Переформировать по шаблону»** (на выбранной дивизии/армии): выбранные полки перераспределяются в дивизии выбранного шаблона; сколько целых дивизий получилось — столько
  и создаётся, остаток полков остаётся в дивизии «вне шаблона» (резерв). Команда `reform_to_template` — через `GameAction`, без потери полков и организации (организация усредняется).
- **Обновление шаблона** автоматически применяется ко **всем дивизиям, созданным по нему**, во всех армиях: слоты, которых нет в дивизии, становятся «недобором»
  (заполняются новыми призывами/пополнением), лишние полки выходят в резерв «вне шаблона» той же армии. Армии сохраняют свои шаблоны.
- Дивизии, собранные из нового набора, сразу создаются по шаблону.

### 4.3 Остальное
- Генералы и фельдмаршалы: генерал командует армией, фельдмаршал — группой армий; черты — в общей формуле снабжения и в бою (раздел 1). `LeaderInstance` сейчас привязан к одной
  группе: расширяем до армий и групп армий.
- Бой, потери, организация и передвижение работают с дивизиями. Самая объёмная часть: `War.cpp`, `UnitInstanceGroup`, ИИ, интерфейс.
- **Набросок конструктора шаблонов** (ваш скриншот 2) — только набросок на этапе 8: список шаблонов, слоты, итоговые параметры (атака, защита, организация, ширина, потребность в снабжении, стоимость).
  Подробности — позже.

## 4б. Конструктор шаблонов дивизий (по вашему описанию 2026-10-29, версия плана 5)

Заменяет простой шаблон «число полков по четырём видам» (этап 4) настоящим конструктором в духе HoI4 (ваши два скриншота). Окно «Конструктор дивизий» в стиле Victoria 2.

### Структура шаблона
```
        Поддержка │ Боевые подразделения
 доп. роты        │  шеренга 1   шеренга 2   шеренга 3   [шеренга 4]  [5]  [6]
 (слева)          │  ряд 1       ряд 1       ряд 1       ...
                  │  ряд 2       ряд 2       ряд 2       ...
                  │  [ряд 3]     ...
                  │  [ряд 4]
```
- **Шеренги** (колонки) — всего 6, **открываются технологиями**, по умолчанию открыто **3**. Это ширина дивизии (`DIVISION_RANKS_MAX = 6`, `DIVISION_RANKS_DEFAULT = 3`).
- **Глубина** (ряды в шеренге, «линии») — максимум **4**, открывается технологиями, по умолчанию открыто **2** (`DIVISION_DEPTH_MAX = 4`, `DIVISION_DEPTH_DEFAULT = 2`). Каждая шеренга
  заполняется отдельно (в одной 1 ряд, в другой 2 — средняя глубина 1.5).
- **Дополнительные роты** (поддержка: артиллерия, инженеры, разведка, снабжение…) открываются технологиями, **стоят дополнительных ресурсов** и **привязаны к шеренге** — у каждой
  шеренги свои слоты рот (так я понял «к каждой шеренге»; если нужно иначе — один общий столбец слева, как на скриншоте, — скажите). Дают бонусы атаки/защиты/укреплённости/разведки.
- Клетка боевого подразделения: тип полка (пехота, кавалерия, артиллерия и т.д.; «типы войск» — отдельная задача позже) или пусто. Закрытые клетки — замок с подсказкой, чем открывается
  (как на скриншоте 2).
- Хранится в состоянии страны (в хеше и в сохранении), создаётся/меняется командами `GameAction` (`create/update/delete_division_template` расширяются клетками и ротами). Автообновление
  дивизий шаблона, «вне шаблона», «переформировать по шаблону» — как в этапе 4, только слоты теперь клетки сетки. Миграция: стандартный шаблон 3 пехоты + 1 кавалерия кладётся в сетку
  3 шеренги × (пехота; в последней шеренге второй ряд — кавалерия) — **уточните, нужно ли так**.

### Показатели шаблона (панель справа, три колонки как на скриншоте)
| колонка | показатель | от чего зависит |
|---|---|---|
| **Базовые** | макс. скорость | тип войск (самый медленный полк) |
| | вес | число и тип войск (нужен флоту: перевозка) |
| | прочность / организация | сумма по полкам, технологии |
| | разведка | технологии и доп. роты |
| | скорость оккупации | технологии (может стать мгновенной) |
| | расход припасов | потребность полков (формулы снабжения, раздел 3) |
| **Боевые** | **атака** (возможный урон) | технологии, современное снаряжение (винтовки, артиллерия), доп. роты |
| | **защита** | считается так же, как атака |
| | **ширина фронта** | число открытых используемых шеренг |
| | **глубина** | средняя по шеренгам (напр. 1.5) |
| | **укреплённость** | технологии и доп. роты |
| **Стоимость** | люди, винтовки, патроны, консервы (и артиллерия по типам) | состав шаблона |

- **Атака** в шаблоне — это *возможный* урон. *Реальный* урон в бою зависит от того, какие винтовки и артиллерия реально выданы (будет несколько поколений, новые дороже и открываются
  технологиями; запас каждого поколения — товар/снаряжение у страны).
- Подсказка к каждому числу — разбор формулы из defines (раздел 7а), строится в C++ из тех же чисел.

### Бой (следующий большой этап после шаблонов; сейчас бой по полкам)
- Урон дивизии пропорционален **ширине фронта**: у противника ширина вдвое меньше (при одинаковой глубине) — он наносит вдвое меньше урона.
- **Глубина** определяет, как долго дивизия держится: чем глубже, тем дольше её уничтожать.
- Реальный урон = возможный урон × качество выданных винтовок/артиллерии × снабжение армии (уже есть, этап 3) × бонус генерала (этап 5).
- Бой переезжает с полков на дивизии вместе с этим, потому что фронты (этап 6) уже раскладывают дивизии по линии.

### Работы (этап 8а–8в, вместо прежнего «набросок конструктора»)
- **8а** (≈5 дней) модель шаблона-сетки, defines (`ov_army`: шеренги, глубина, роты, коэффициенты), расчёт показателей, технологии-заглушки (шеренги/глубина/роты), миграция, команды, тесты.
- **8б** (≈4 дня) окно конструктора (клетки, замки с подсказками, три колонки показателей, «Сброс», «Клонировать», расчётная стоимость).
- **8в** (≈4 дня) нижняя панель армий (скриншот 1) и список шаблонов.
- **10** Бой на дивизиях (ширина/глубина/реальный урон, поколения снаряжения) — после согласования числовой модели.

### Вопросы, которые нужно закрыть до 8а

2. Сколько слотов рот открыто по умолчанию и чем открываются остальные (технологии «глубоких атак» и т.п.)?
3. Типы клеток на первом шаге: только пехота и кавалерия + артиллерия как рота, или сразу все типы полков Vic2?
4. Поколения винтовок/артиллерии: отдельные товары (`rifles_1…`) или уровни одного товара с множителем?

## 5. Фронты и планы операций (задача D)

- Фронт строит игрок по границам провинций (линия, как в HOI4): список соседних провинций вдоль границы (основа — существующий `build_border_line`, но задаёт игрок).
  Армия назначается на фронт; **дивизии армии равномерно распределяются по линии** (`order_front_armies` обобщаем с армий на дивизии).
- План наступления: стрелки по границам провинций от провинции к провинции. Галочка у армии запускает операцию «наступление» (пока только оно; оборона, высадка, окружение — позже).
  На каждой провинции бой и захват; снабжение пересчитывается по разделам 1–3.
- Хранение: фронты и планы — состояние симуляции (в хеше, в сохранении), команды игрока (`create_front`, `set_front_line`, `assign_army`, `create_plan`, `start_plan`) через `GameAction`.
- Интерфейс: рисование на карте, нижняя панель армий и планов (ваш скриншот 1).

## 6. Интерфейс армий

- **Нижняя панель** как в HOI4: портреты фельдмаршалов/генералов, число дивизий/полков, организация и полнота, кнопки приказов («Планы операций»), статус снабжения армии
  (приоритет, поставка %). «+» — назначить генерала или создать армию.
- **Правый список** (оригинальный): номер, имя армии и число дивизий (для флота — число кораблей).
- **Вкладка армий** в военном меню: глобальный приоритет снабжения, список армий с поставкой/уровнем, кнопки фронта и плана, управление шаблонами.

## 7. Порядок работ (каждый этап — отдельный коммит с тестами, версия симуляции растёт)

1. **Лимит снабжения провинции** (раздел 1, без территорий): defines `ov_supply`, `ProvinceInstance::supply_limit`, подпись и подсказка, режим карты «Снабжение», тесты
   («равнины > горы», «дорога поднимает», кап 0…1), хеш. + раздел справочника «Снабжение». ≈2 дня.
2. **Коэффициент территории** (раздел 2): кто «свой» (союз, союзники по войне), бонус родной земли, BFS, технологии-заглушки; тесты на каждую строку таблицы. ≈1.5 дня.
2б. (отдельного договора нет: проход войск включает снабжение — `has_military_access_to` подключается в `is_supply_friend`, подсказка в окне дипломатии «включает снабжение».) ≈0.2 дня.
3. **Доставка, приоритет, соседние провинции** (раздел 3): поставка по армии, потеря, повышенный/максимальный приоритет, добор у соседей 75%, глобальный и ручной приоритет, интерфейс. ≈3 дня.
4. **Режимы армии по технологии, дивизии, шаблоны и «вне шаблона»** (раздел 4: слияние/разделение групп полков как в Victoria 2 для нецивилизованных, кнопка переформирования,
   автообновление шаблонов, без конструктора): структура, миграция стартовых армий и вестернизации, бой на дивизиях. ≈6–7 дней.
5. **Генералы/фельдмаршалы** (доступны только с технологией; черты в общей формуле, группы армий). ≈2 дня.
6. **Фронты** (рисование, распределение дивизий). ≈3 дня.
7. **Планы наступления** (стрелки, запуск галочкой). ≈3 дня.
8. **Нижняя панель и набросок конструктора шаблонов.** ≈4 дня.
9. **Справочник**: каркас и разделы «Армия», «Фронты» (раздел «Снабжение» делается в этапе 1 и дописывается в 2–3). ≈2 дня.

Этапы 1–3 вместе — снабжение (то, что вы просили в первую очередь); 4–8 — армия, фронты и операции.

## 7а. Подсказки с формулами и справочник в игре

1. **Подсказки с разбором формул** на каждое число:
   - лимит провинции: «местность X + тип Y = база; × железная дорога (+10% × N) × технологии × территория (причина: 1 захваченный сосед → 90%…) × (1 + генерал − дебафы) = ёмкость;
     нагрузка Z; добор у соседей +W (75% свободного); поставка d%»;
   - поставка армии: потребность, отправлено (множитель приоритета), доставлено, потеряно, сверх нормы из запаса;
   - уровень снабжения армии (цель, 2%/день), влияние на атаку/защиту/организацию;
   - дивизия: параметры из шаблона, отклонения; фронт: ширина, дивизий на провинцию; план: этапы.
   Подсказки строятся **в C++ из тех же чисел и defines**, что и расчёт (функция «разбор» возвращает и итог, и список слагаемых): текст не может разойтись с формулой.
   Значения defines подставляются в текст (изменили `openvic_defines.lua` — подсказка показывает ваши числа). Самотест: сумма/произведение слагаемых разбора = итог.
2. **Справочник** — в игре, на русском и английском (`.csv`, как остальные строки):
   - доступен **из меню** (пункт «Справочник» в главном меню и в игровом меню паузы) и **прямо во время игры** как вкладка/окно по **сочетанию клавиш**;
   - сочетание — новое действие `open_guide` в `ControlsGlobal.gd` (группа «UI»), по умолчанию **F1**; оно появляется в настройках на экране управления, где его можно переназначить
     (там уже есть Keychain); то же — для других новых окон (армии/шаблоны/фронты) по мере появления;
   - разделы: «Снабжение», «Армия и шаблоны», «Фронты и операции», «Бюджет и закупки армии», потом «Грамотность», «Партии и решения». В тексте живые числа из defines, ссылки между
     разделами и пример расчёта на реальной провинции игрока; из подсказок ссылка «Подробнее» открывает нужный раздел.
3. Документация для разработчиков остаётся в `docs/` (`MILITARY_SUPPLY.md` обновляется вместе с кодом).

## 8. Принятые решения (все вопросы закрыты)

- Железные дороги складываются; «свои» — союзники, союзники по войне и страны, давшие проход войск (он включает снабжение, отдельного договора нет); сфера влияния, вассалы,
  марионетки и протектораты автоматически не «свои».
- Таблица расстояний верна; нагрузка общая на провинцию, приоритет у войск на ней; черты генералов только в общей формуле; снабжение не больше 100%.
- Технологии лимита — по стране армии; бонус родной земли 5% (+5% технологией).
- Страны с проходом войск — снабжение как у союзных. Без прохода войск и не в войне — вход закрыт.
- Режим карты: синий 100–110%, голубой 111–125%, зелёный 126–149%, тёмно-зелёный 150%+ (по моему прочтению «зелёный 126+» — тёмно-зелёный оставлен для 150%+); провинции без армий —
  по эталонной нагрузке в одну стандартную дивизию (`SUPPLY_MAP_REFERENCE_LOAD`), при выбранной армии — по её потребности.
- Уведомления о потере снабжения — да, с выключателем. Флот пока на старой схеме. Нехватка товара при повышенном приоритете — армия получает сколько есть.
- Технология «Организация армии» — только цивилизованным; без неё группы полков (слияние/разделение как в Victoria 2), только ручное управление, без шаблонов, генералов, фронтов и планов.
  Генералы нецивилизованных стран со старта снимаются с назначения, но не удаляются.
- Шаблон цивилизованных стран по умолчанию: 3 пехотных полка + 1 кавалерийский.
