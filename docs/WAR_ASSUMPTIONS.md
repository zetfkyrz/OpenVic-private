# Допущения армии: оружие, шаблоны, баланс

Здесь записано всё, что взято «с потолка» или оценено, чтобы потом это можно было пересмотреть. Числа боя и экономики оружия — стартовые и ориентировочные.
Правило: если значение по умолчанию меняет результат игры (строка `CHECKSUM` у `headless -b <Vic2> -e 60`), изменение попадает в раздел «Журнал CHECKSUM» ниже с причиной.

### Допущения, которых не было в таблицах
- **Вес** (оценён по историческим образцам, кг одного изделия): rifle_1 4.7 (Brown Bess), rifle_2 4.1 (Enfield 1853), rifle_3 4.2 (Шаспо, Мартини-Генри, Дрейзе ≈ 4 – 4.7), rifle_4 4.1 (Лебель, Мосин, Маузер ≈ 4 – 4.2); field_gun_1 1200 (орудие «Наполеон» ≈ 1200 с лафетом), field_gun_2 1300, field_gun_3 1500, field_gun_4 1150 (75-мм образца 1897 ≈ 1150 в боевом положении). Вес нужен флоту (перевозка) и показателю «вес» шаблона.
- **Расход патронов** `ammo_per_day` (единиц `ammunition` на одно изделие в день боя; пока не используется, поле готово для подэтапа патронов): винтовки 0.020 / 0.025 / 0.040 / 0.060, орудия 0.15 / 0.20 / 0.30 / 1.00. Оценено пропорционально скорострельности.
- **Дальность картечи** field_gun_1: 300 м (из таблицы), у остальных `canister_range` не задан.
- **Цены** возрастают с поколением примерно в 1.5 раза за шаг для винтовок (37 → 55 → 80 → 115) и 1.4–1.5 для орудий (60 → 90 → 130 → 185). Базовая цена товара Vic2 `small_arms` = 37, `artillery` = 60 — это поколение 1.
- **Цвета и иконки товаров**: иконка новых поколений пока общая с `small_arms` / `artillery` (кадр спрайта `GFX_resources` = индекс товара + 2 не расширяется без правки интерфейса); цвет — оттенок цвета старого товара.
- **Стоимость** `cost = { <id> = 1 }`: один предмет оружия стоит один такой товар (рецепты производства — отдельными файлами `ov_data/common/ov_production_types`, подпункт 5).
- **Миграция товаров**: `small_arms` становится `rifle_1`, `artillery` становится `field_gun_1` при загрузке (псевдоним), файлы Vic2 (история, юниты, здания, рецепты) не меняются. Корабельные пушки остаются на `field_gun_1`.
- Патроны (`ammunition`) остаются одним товаром, поколения патронов отложены (поле `ammo_good` в данных есть).

## 2. Шаблон дивизии (по ответам владельца 2026-10-29)

- Шеренги (колонки): всего 6, по умолчанию открыто 3. Линии (ряды): максимум 4, по умолчанию 2. Дополнительные роты: у каждой шеренги свои слоты, 1 открыт, максимум 4, открываются по технологиям (`ov_war`: значения по умолчанию; пределы берутся из разблокировок и модификаторов страны).
- Простого режима (число полков) нет, сетка полностью заменяет его.
- Стандартный шаблон: 4 пехоты 2×2 (ширина × глубина) и 2 кавалерии 1×2; всего 3 шеренги × 2 ряда.
- Показатели шаблона: атака, защита, **прочность** (зависит от технологий, числа войск и поколения оружия), организация, укреплённость, ширина, глубина, плотность, вес, скорость, разведка, скорость оккупации, надёжность, стоимость.
- Веса линий (рядов) глубины: `[1.0, 0.5, 0.25, 0.125]`; с технологией сдвига — `[1.0, 1.0, 0.5, 0.25]`. Урон пропорционален ширине фронта, глубина — прочность.
- Формулы боя (окно превосходства, подавление, окопы, вскрытие, дни оккупации по ступеням) пишет владелец; они собираются в одном файле `military/BattleFormulas.cpp`, чтобы их можно было заменить.
- Смена типа продукции на фабрике мгновенная и без штрафа эффективности, параметров переналадки нет.
