   Сейчас интерпретатора нет. Делать ли полноценный интерпретатор (большая отдельная работа, но разблокирует ~6 пунктов)
   или оставить упрощённые модели? По умолчанию: интерпретатор делаем отдельным этапом после остальных.
2. **Совместимость сохранений.** Сохранение = реплей; любое изменение правил симуляции делает старые сохранения
   недействительными. Достаточно ли версионной метки с предупреждением «сохранение из другой версии» (по умолчанию да)?
3. **Калибровка экономики** без прогона на ваших данных невозможна «по ощущениям»: какие целевые показатели считать

4. **Конфиг-файл параметров.** Формат и место: по умолчанию `game/common/openvic_tuning.cfg` (ConfigFile Godot) или JSON рядом
   с игрой — симуляция читает через headless-путь. Устроит JSON `openvic_tuning.json` в корне данных игры?

## Допущения по ответам владельца (2026-10-23)
- Формат конфигов: расширяем механизм `defines.lua`: необязательный `common/openvic_defines.lua` с тем же парсером (см. `CONFIG_PROPOSAL.md`). Допущение: не править ванильный `defines.lua`.
- Сохранения: версия в заголовке, при несовпадении версии — сообщение с причиной и предложением «открыть всё равно» (реплей другой версии почти всегда даёт другое состояние; настоящая миграция реплея возможна только для изменений формата записи, не правил симуляции).
- Кредиты в PENDING_PLANS помечены [частично]; их код в этапе 1 не затрагивается.

## Этап 1 (вынос констант): неясные места и что осталось в коде
- `ov_ai.WAR_DECISION_SALT = 7` — «соль» кубика решения об объявлении войны (в прежнем коде просто число 7). Смысл другого
  значения нет, названо по назначению; менять незачем, если нет желания перетасовать, какие страны воюют. Нейтральное имя оставлено.
- Хеш-константы кубика (`0x9E37...`, сдвиги 29/32, модуль 100 в `CountryAI.cpp`, `2654435761`/`40503` в `War.cpp`, хеш предложения в `Peace.cpp`)
  — часть алгоритма «детерминированного кубика», не параметры баланса; оставлены в коде. Если нужно, можно вынести «число граней кубика».
- Календарные константы (`365` дней в году, `12` месяцев, `/12` в годовой ставке роста) оставлены: это не баланс.
- Шкала `0..10` воинственности/сознательности и `[0, 1]` для долей — структура модели, оставлена.
- Кредиты (`economy/credit/*`) не тронуты по вашему указанию; их литералы (`INVESTMENT_MAX_PAYBACK_YEARS`, `FRIEND_RELATIONS` и т. д.)
  выносятся при переделке в группу `ov_credit` (заготовка со сроками, задержкой выплат, мин./макс. процентом уже есть, значения 0 = не заданы).
- Параметры оригинального кода OpenVic (`CountryInstance`: `PRIMITIVE_CIVILISATION_PROGRESS`, формула военной мощи и т. п., `Pop.cpp`: границы) —
  чужой код, не тронут.
- `MAX_ENTRIES` журнала уведомлений, число скоростей, размеры буферов — технические, не вынесены.
- Мы выносили ключи в том коммите, где менялся файл (а не все заранее): так каждый коммит самодостаточен и проверяем CHECKSUM.
