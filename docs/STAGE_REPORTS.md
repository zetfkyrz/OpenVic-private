## Этап 1 — вынос констант в конфиг (2026-10-24)

`-P -X -e 400` (политика, восстания, исследование). После **каждого** файла прогоны повторялись и сравнивались побайтно с эталоном.

Итого 216 параметров (+5 ключей-заглушек `ov_credit`, не используются). Округление: параметры-доли хранятся как `Rate` (целое число 1/10000), `rate.of(x)` даёт тот же `fixed_point_t`,
что прежнее `x * n / d`, поэтому расхождений CHECKSUM не возникло; значения по умолчанию не менялись.

Дополнительно после последнего файла: прогон `-e 600` (одна строка CHECKSUM, отчёты ECON/POP, 8 объявленных ИИ войн, мирные договоры, колонизация,
восстания) на сборке до этапа и на сборке после — файлы вывода совпали побайтно. Пример `docs/openvic_defines.example.lua`, загруженный как
`common/openvic_defines.lua`, даёт тот же хеш (`6108771f8a2ca199`), что и встроенные значения, без предупреждений; изменённые значения
(`ov_population`) меняют ход игры; неверный ключ, не число, значение вне диапазона и дробное в целом — предупреждения с именем файла и ключа.

## Этап 4 — разбиение (предложение, 2026-10-24)
Этап слишком большой для одного шага (пять независимых направлений, часть с интерфейсом, который нельзя проверить без Godot), поэтому делю на части, по одному коммиту на пункт:
- **4a Сохранения:** загрузка `.ovsave` из главного меню и лобби (общий список файлов, предпросмотр заголовка, предупреждение «открыть всё равно»), выбор сложности (допущение — в `QUESTIONS.md`).
- **4b Производство (интерфейс + действия):** вкладка инвестиций, фильтры и сортировка, приоритет найма (`priority`), удаление завода (`delete_factory`).
- **4c Калибровка экономики:** только после вашего согласования `BALANCE_TARGETS.md` и решения по золоту.
- **4d Войны, по частям:** 4d-1 мобилизация, усталость от войны, follow, стойки; 4d-2 оправдание войны (`justify_war`, поводы к войне), ручной `call_ally`; 4d-3 вассалы и освобождение стран.
- **4e Флот и блокада:** ИИ использует флот (плавает, блокирует, перевозит), блокада режет торговлю и налоги.
- **4f Дипломатия:** вкладки «Великие державы», «Войны», «Кризис», константы из defines, ответы получателя по отношениям и логике (не «принимает всё»).
Порядок по умолчанию: 4a → 4d → 4e → 4f → 4b → 4c. После каждой части: сборка, автотесты, отдельный коммит, обновление `PENDING_PLANS.md`.

## Этап 4c — калибровка, промежуточный статус (2026-10-24)
Сделано (сим-коммиты `c9f5071`, `c6e74fe`, `0f67f0f`, версия симуляции 3):
- **Причина застрявших цен найдена и исправлена при правилах Vic2:** в `GoodMarket` направление шага цены было перепутано (при избытке предложения цена росла к границе 5×, при дефиците падала к 0.22×). Правила Vic2 не менялись.
- **T1:** заниженный старт (0.76) — частично из-за тестовых значений денег попов; добавлен параметр `ov_economy.POP_START_SAVINGS_DAYS` (по умолчанию 0 = как раньше; при 30 дн. страты выравниваются около 0.83, упираясь в предложение).
- Параметр `ov_economy.ARTISAN_AVAILABILITY_WEIGHT` (ремесленники учитывают наличие сырья при выборе производства; по умолчанию 1 = прежнее поведение).
- Инструменты: `headless -B` (отчёт баланса), `-G` (товары/ремесленники/заводы), `-o группа.КЛЮЧ=значение` (переопределение defines без правки файла).
Не решено: за год снова растёт голод (бедные 0.57–0.60), ремесленники (≈17 млн) голодают, заводы закрываются (открыто ≈51–54% при цели ≥80%), цены касаются границ. Следующий шаг — анализ рентабельности заводов с большим числом входов (ткань, стекло, бумага, мебель: throttle 0.20), затем по одному изменению через `openvic_defines.lua`, 1836 цель / 1861 контроль, отдельный коммит с таблицей до/после.
Стартовые сбережения по умолчанию пока НЕ включены (дефолт 0): включение меняет игру — решу после таблицы до/после.
