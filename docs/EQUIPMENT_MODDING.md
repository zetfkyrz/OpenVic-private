# Оружие армии: как менять баланс и добавлять своё одними файлами

Оружие (винтовки, полевая артиллерия) и его товары описаны данными, не кодом. Тут: где лежат файлы, формат, как поменять баланс, как добавить новое поколение
или целую новую линию (осадная артиллерия, пулемёты) без правки C++, как подключить свою систему технологий. Числа по умолчанию и допущения — в [WAR_ASSUMPTIONS.md](WAR_ASSUMPTIONS.md).

## 1. Где лежат файлы

```
ov_data/                                   встроенный корень данных OpenVic (в репозитории рядом с game/ и extension/)
  common/
    ov_equipment/
      lines.txt                            виды оружия («линии»): rifle, field_artillery, ...
      rifles/rifle_1.txt ... rifle_4.txt   по одному оружию на файл
      artillery/field_gun_1.txt ... field_gun_4.txt
      provisional_unlocks.txt              ВРЕМЕННАЯ заглушка разблокировок по году (подпункт 3)
    ov_production_types/<id>.txt           рецепт производства оружия, по файлу (подпункт 5)
  localisation/ov_equipment.csv            названия оружия и линий RU/EN (подпункт 4)
```

Корень `ov_data` грузится **после** Vic2 и **до** модов. Мод кладёт файл с тем же путём (`<мод>/common/ov_equipment/rifles/rifle_2.txt`) и перекрывает встроенный;
файл с новым путём добавляется. Если у оружия из мода тот же `id`, что у загруженного, оно заменяет его (в логе строка `Weapon "x" of <файл> replaces the one of <файл>`).
Папку Vic2 не трогаем. Где ищется `ov_data`: параметр `--ov-data <папка>` у headless, переменная окружения `OPENVIC_DATA_PATH`, иначе папка `ov_data` в текущей
папке, рядом с исполняемым файлом или в одной из родительских. Игра в редакторе берёт `<репозиторий>/ov_data`; в собранной игре папку кладут рядом с exe.

Порядок загрузки не зависит от файловой системы: сначала Vic2, потом `ov_data`, потом моды по порядку; внутри корня файлы отсортированы по пути. Любой файл можно сломать
безопасно: файл с синтаксической ошибкой, неизвестной линией, пропущенным обязательным ключом или значением вне диапазона пропускается с предупреждением (файл, строка, причина),
остальные грузятся, игра не падает. Неизвестный ключ — предупреждение, остальное из файла читается.

## 2. Виды оружия: `lines.txt`

```
rifle = {
	icon = "small_arms"                      ключ значка линии
	name = "EQUIPMENT_LINE_RIFLE"            ключ локализации
	slot = infantry                          слот шаблона: infantry, cavalry, support, special
	unit_types = { infantry guard irregular engineer dragoon }   типы полков (units/*.txt), которые пользуются этим оружием
}
```
Новая линия — ещё один блок здесь и файлы её оружия в любой подпапке `ov_equipment`.

## 3. Оружие: один файл — одно оружие

Папка внутри `ov_equipment` значения не имеет (только порядок: `rifles`, `artillery`, `siege`, ...). Каждый файл — блок с именем `id` оружия. Пример (`rifles/rifle_3.txt`):

```
rifle_3 = {
	line = rifle                  вид оружия (ключ из lines.txt)
	tier = 3                      поколение, 1 и больше
	unlock_key = "equipment:rifle_3"   разблокировка страны, при которой оружие доступно (по умолчанию equipment:<id>)
	attack = 9                    очки атаки изделия в единицах типов полков (units/*.txt)
	defence = 6.5                 очки защиты изделия
	ammo_per_day = 0.040          расход ammo_good на изделие в день боя (необязательно)
	ammo_good = "ammunition"      товар патронов (необязательно; поколения патронов — позже)
	weight = 4.2                  килограммов одного изделия
	cost = { rifle_3 = 1 }        цена изделия в шаблоне, товарами
	flags = { breech_loading }    breech_loading, magazine, smokeless, indirect_fire, canister, shrapnel (список открытый)
	good = {                      товар, которым является оружие; загрузчик регистрирует его сам (подпункт 4)
		id = "rifle_3"            (по умолчанию id оружия)
		replaces = "small_arms"   (необязательно) товар Vic2, который становится этим товаром (псевдоним старого имени)
		base_price = 80           базовая цена на рынке
		icon = "small_arms"       ключ значка товара
		name = "rifle_3"          ключ локализации названия
		colour = { 222 142 34 }   цвет товара
	}
}
```
Обязательные ключи: `line`, `tier`, `attack`, `defence`, `weight`, `good.base_price`. Всё, что не указано, берёт значение по умолчанию.

## 4. Как поменять баланс

Показатели шаблона, которые считаются из этих файлов (атака, защита, прочность, стоимость, расход припасов и патронов), смотрите в окне «Шаблоны дивизий» или командами `headless --dump-template --dump-battle`. Правка одного числа в одном файле: например, чтобы усилить `rifle_2`, открой `ov_data/common/ov_equipment/rifles/rifle_2.txt` и поменяй `attack`.
Мод делает то же, кладя в свою папку файл по тому же пути. Цены — `good.base_price`. Все коэффициенты боя и шаблонов (веса линий, плотность, пределы шаблона) — не в этих файлах,
а в группах `ov_war` / `ov_economy` файла `common/openvic_defines.lua`.

## 5. Как добавить новое поколение и новую линию

Новое поколение винтовки (rifle_5): файл `ov_data/common/ov_equipment/rifles/rifle_5.txt` с `line = rifle`, `tier = 5`, своим `good` и `unlock_key` (по умолчанию
`equipment:rifle_5`). Новая линия, например осадная артиллерия:

1. В `lines.txt` блок:
   ```
   siege_artillery = { icon = "artillery" name = "EQUIPMENT_LINE_SIEGE" slot = special unit_types = { siege_gun } }
   ```
2. Файл `ov_data/common/ov_equipment/siege/siege_1.txt`:
   ```
   siege_1 = {
   	line = siege_artillery
   	tier = 1
   	attack = 8
   	defence = 2
   	weight = 2000
   	good = { base_price = 120 }
   }
   ```
3. Перезапустить игру. Оружие подхватится без правки кода (автотест `equipment: a weapon of the new line is loaded without code` проверяет именно это).

Дальше (подпункты 3–6) к оружию добавляются разблокировки, рецепты производства и показ в шаблоне; новое оружие по тем же файлам попадёт и туда.

## 6. Разблокировки и подключение своей системы технологий

Слой разблокировок **не зависит от системы технологий**. Что бы ни открывало оружие, формацию или роту поддержки (технология, событие, решение, консольная команда),
оно выдаёт стране ключ и, если надо, модификатор. Оружие, боевая математика и шаблоны читают только ключи и модификаторы, поэтому свою систему технологий можно подключить
без правки оружия и боя. Код: `military/Unlocks.hpp/.cpp`, `CountryInstance::grant_unlock` и соседние.

### Ключи
Строка `<вид>:<id>`, обе части непустые и без пробелов. Три вида, которые читает игра: `equipment:<id оружия>`, `formation:<id>`, `support_company:<id>`; мод может ввести свой вид.
Ключ хранится в `CountryInstance` отсортированным списком; набор ключей входит в хеш состояния (`StateHash`), поэтому сохранения (реплей) и проверка `CHECKSUM` видят его.

| вызов | что делает |
|---|---|
| `country.grant_unlock("equipment:rifle_2")` | выдать ключ; `true`, если набор изменился (неверный ключ и повторная выдача дают `false`) |
| `country.revoke_unlock(key)` | отнять ключ |
| `country.has_unlock(key)` | есть ли ключ |
| `country.get_unlock_keys()` | все ключи (отсортированы) |
| `is_equipment_unlocked(country, weapon)` | у страны ключ `weapon.unlock_key` (по умолчанию `equipment:<id>`) |
| `get_best_equipment(equipment_manager, country, "rifle")` | оружие линии с самым высоким поколением среди открытых |

Ключ оружия задаётся в файле оружия строкой `unlock_key`; если её нет, он `equipment:<id>`. Поле технологии в файлах оружия **не используется**.

### Числа: обычные модификаторы страны
Числовые пределы шаблона — эффекты существующей системы модификаторов (как `supply_limit` или `combat_width`), которые складываются по правилам проекта:

| эффект | действие | по умолчанию (`ov_war`) | максимум |
|---|---|---|---|
| `max_columns` | +N шеренг (колонок) в сетке шаблона | `TEMPLATE_RANKS_DEFAULT` = 3 | `TEMPLATE_RANKS_MAX` = 6 |
| `max_rows` | +N линий (рядов) глубины | `TEMPLATE_DEPTH_DEFAULT` = 2 | `TEMPLATE_DEPTH_MAX` = 4 |
| `max_company_slots` | +N слотов доп. рот у каждой шеренги | `TEMPLATE_COMPANY_SLOTS_DEFAULT` = 1 | `TEMPLATE_COMPANY_SLOTS_MAX` = 4 |
| `density_reduction` | уменьшение плотности построения (доля 0..1) | 0 | 1 |
| `row_weight_shift` | сдвиг весов рядов: 0 — `[1, ½, ¼, ⅛]`, 1 — `[1, 1, ½, ¼]` | 0 | 3 |

Эффекты зарегистрированы как технологические (`register_technology_modifier_effect` в `ModifierManager.cpp`), поэтому их можно писать в блоке модификатора технологии, изобретения,
события. Пример записи в файле технологии (формат Vic2/OpenVic, тот же, что у `supply_limit`, `combat_width`):

```
my_rifled_tactics = {
	max_columns = 1
	max_rows = 1
}
```
Предел страны считает `get_template_limits(instance_manager, country)`: значение по умолчанию + сумма эффекта в модификаторах страны, зажатое между 1 (для рот — 0) и максимумом из `ov_war`.
Значения по умолчанию и максимумы — в `common/openvic_defines.lua` (группа `ov_war`, ключи `TEMPLATE_*`).

### Модификатор, который даёт разблокировка
Если свою систему технологий ещё не подключили к модификаторам страны, разблокировка может отдать стране готовый `Modifier`:
`country.add_unlock_modifier(modifier)` / `remove_unlock_modifier(modifier)`. Он добавляется в сумму модификаторов страны каждый день, пока выдан, и входит в хеш состояния
(по `identifier`). Объект `Modifier` должен жить дольше игры (страна хранит указатель).

### Как подключить новую систему технологий
1. Выдавать ключи в момент открытия: `country.grant_unlock("equipment:rifle_3")` (оружие), `"formation:<id>"`, `"support_company:<id>"`. Вызывать из тика симуляции (в одном потоке), так как сохранения — реплей: состояние восстанавливается тем же кодом, который выдаёт ключи.
2. Числа писать модификаторами технологии (эффекты из таблицы выше) или через `add_unlock_modifier`.
3. Выключить заглушку: в `common/openvic_defines.lua` группа `ov_war`, `PROVISIONAL_UNLOCKS_ENABLED = 0` (или удалить файл заглушки). Больше ничего менять не нужно: оружие, шаблоны и бой читают только ключи и модификаторы.
4. Если нужно оружие, которое не открывается ничем в игре, дать ключ в сценарии или событии.

### ВРЕМЕННАЯ заглушка по году: `provisional_unlocks.txt`
`ov_data/common/ov_equipment/provisional_unlocks.txt` (в шапке пометка TEMPORARY) выдаёт **каждой стране** ключи и модификаторы по году игры, пока нет новой системы технологий. Годы в файле, не в коде.
Блок `step = { year = <год> unlock = { "<ключ>" ... } modifier = { <эффект> = <число> ... } }`: в первый день года шага страна получает ключи и модификатор. Шаги применяются по годам, один раз
(у страны счётчик шагов). Файл мода с тем же путём заменяет встроенный целиком. Отключается одной настройкой `ov_war.PROVISIONAL_UNLOCKS_ENABLED = 0`.
Строка в `docs/PENDING_PLANS.md`: «заглушка разблокировок ждёт новой системы технологий».
